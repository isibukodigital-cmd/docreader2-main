Providers used by the current application

  • Supabase — authentication and persistent Postgres/pgvector storage for workspace metadata, extracted document chunks, embeddings and audit events. The selected data region depends on the deployed Supabase project.
  • Groq — hosted language-model provider when configured. The question and authorized retrieved passages are sent for response generation if selected or reached as a fallback.
  • OpenRouter — hosted language-model provider when configured. The application asks OpenRouter to route to providers that do not store/train on prompts and sends data_collection=deny; this does not independently verify downstream behavior.
  • Cerebras — hosted language-model provider when configured. The question and authorized retrieved passages are sent for response generation if selected or reached as a fallback.
  • NVIDIA NIM — hosted language-model provider when configured. The question and authorized retrieved passages are sent for response generation if selected or reached as a fallback.

Configuration and data handling

Supabase is used for authentication and storage in the supported deployment. When the hosted LLM backend is enabled, one configured provider is selected at random as the starting provider for each request; if it fails, the remaining configured providers are tried in their configured order. Any provider reached in that chain receives the question and authorized retrieved passages. Local/extractive deployments do not send prompts to these hosted model providers through this application.

Provider locations, current downstream model providers, applicable data-processing agreements, retention/deletion windows, and onward subprocessors have not been independently confirmed here. Review current vendor terms and configure customer disclosures before enabling hosted-model processing for sensitive content.
